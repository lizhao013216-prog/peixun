# 航维 · 保障业务共性平台 Demo

基于仓库内的三份 Demo 方案实现，覆盖操作训练、维修培训、保障筹划与演练，以及模拟施工、改进归档的完整业务主线。界面采用中文专业工作台布局：深蓝导航、浅色内容区、统一状态、交互设备示意图、甘特图和过程记录。

**Vue 3 + TypeScript + Vite / Java 17 + Spring Boot / H2 文件数据库。** 虚拟现实能力通过 `VirtualPlatformPort` 模拟适配器提供；业务审批、计分、排程、费用、库存账本和版本记录由后端实际计算、持久保存。

## 快速启动

需要 Node.js 24、Java 17、Maven 3.9。首次安装依赖需要网络。

终端一：

```bash
cd frontend
npm ci
npm run dev
```

终端二：

```bash
cd backend
mvn spring-boot:run
```

打开 **http://127.0.0.1:5173**。默认工作区只有基础资源，课程、任务、成绩等由实际操作生成。页面右上角可切换演示身份；这是一套便于展示审批分工的演示身份机制。

在项目根目录执行以下命令，可新增一套完整案例：

```bash
node scripts/load-demo.mjs
```

刷新页面，选择“完整业务演示案例”工作区。脚本按业务接口逐步完成两类课程发布、训练、三种演练、P1施工、返工复查、P2验证、审核退回再提交与发布；不会覆盖原工作区。

共33个业务页面。具体入口与角色操作见 [演示操作手册](docs/演示操作手册.md)。

## 构建与验证

```bash
# 项目根目录
npm --prefix frontend ci
npm --prefix frontend run build
mvn -f backend/pom.xml verify

# 构建完成后，使用一个后端进程提供页面和API
cd backend
java -jar target/peixun-demo-1.0.0.jar
```

此时打开 **http://127.0.0.1:8080**。运行 JAR 时请保持工作目录为 `backend`，静态页面位于 `../frontend/dist`。

浏览器验收：先完成上述构建，再安装浏览器并执行脚本。

```bash
cd frontend
npx playwright install chromium
cd ..
node scripts/verify-browser.mjs
```

验收脚本自动启动独立8081端口服务，使用内存数据库建立完整案例，检查页面、布局和复盘，不影响本地业务数据库。截图和记录写入忽略提交的 `test-results/`。

可选容器启动：`docker compose up --build`，打开8080端口。容器配置已提供；本次验证以本地 Node/Java 运行方式为准。
