# 数据迁移与兼容说明

## 版本与策略

- 当前工作区快照结构版本：`schemaVersion = 7`。
- 迁移入口：后端 `WorkspaceMigration`。读取旧快照时先在内存深拷贝上迁移，不原地修改传入对象；重复执行结果相同。
- 本轮未对用户数据库 `backend/.data/peixun.mv.db` 执行批量迁移、清空或重置。自动化验证全部使用独立 H2 内存库。

## V1 到 V2 映射

| 旧对象 | V2 补充字段/规则 |
| --- | --- |
| `courses` | 保留已有 `domain`；缺失时按旧培训数据兼容为 `MAINTENANCE` |
| `assignments` | 优先继承关联课程 `domain`，找不到时兼容为 `MAINTENANCE`；补 `courseVersion` 的新任务由命令生成 |
| `attempts` | 优先保留自身领域，否则按课程/任务推导 |
| `feedback` | 按课程或尝试补领域 |
| `assets` | 缺失时补 `ownerSystem=SHARED`、`visibility=SHARED`、`sharedWith=[三领域]` |
| 任务、预案、演练、施工、归档、对比、评估 | 补 `domain=SUPPORT`、`purpose=BUSINESS` |

迁移不会复制课程、任务和记录，不重新计算旧分数，不改变旧版本号和来源 ID。`WorkspaceMigrationTest` 使用真实 `schemaVersion=2` 夹具连续迁移到 V7 两次：新工程、场景、关系、模板、课程组织和训练归档数量稳定，旧课程、任务、93 分尝试、保障任务、保障预案及原模板对象保持逐项相同。

## V2 到 V3 映射

| V2 对象 | V3 行为 |
| --- | --- |
| `assets` | 补 `familyId`、`editRevision`；旧 `ownerSystem=SHARED` 素材继续只读共享 |
| 全局 `scene/topology` | 保留原字段，同时分别生成确定 ID 的操作、维修只读兼容工程及独立场景/关系快照 |
| `templates` 中带场景的旧模板 | 映射为只读 `systemTemplates` 记录，原模板不删除 |
| 新集合 | 增加 `simulationProjects`、`scenes`、`topologies`、`systemTemplates` |

2→3 不重写 1→2 的领域推导，不修改旧课程、尝试、成绩和来源 ID。迁移在加锁读取时持久化一次并提升工作区修订号；再次读取保持幂等。

## V3 到 V4 映射

| V3 对象 | V4 行为 |
| --- | --- |
| `assets` | 按已有素材类型补有限动作、输入/输出端口、数据类型和允许的状态字段 |
| `scenes.objects` | 按所引用素材补同一份对象能力声明，保留对象 ID、位置、视图和初始状态 |
| 新集合 | 增加 `simulationPreviews`，用于保存彼此隔离的调试实例及事件；不会复用场景初始状态作为运行状态 |

3→4 不创建默认连接或规则，不推断用户的联动意图，不修改旧课程、训练成绩和保障业务对象。调试实例只由明确的“新建实例”命令创建。

## V4 到 V5 映射

| V4 对象 | V5 行为 |
| --- | --- |
| `systemTemplates` | 旧记录缺失时补 `familyId`、`visibility=PRIVATE`、空 `sharedWith` 和旧模板使用说明 |
| 新发布版本 | 直接写入不可变 `sceneSnapshot`、`topologySnapshot`、素材依赖、来源工程、版本链及发布审计信息 |
| `templates.type=PLAN` | 不迁移到新模板生命周期，不修改、不删除，继续由保障预案业务使用 |

4→5 不为旧记录伪造场景或关系快照；旧兼容模板保持只读。只有通过当前发布检查的新版本才可调试、实例化和创建修订。

## V5 到 V6 映射

| V5 对象 | V6 行为 |
| --- | --- |
| 新集合 | 增加空 `curricula`，用于 P3 课程目标、受众和课时组织 |
| 旧 `courses` | 保持原对象、交互版本、步骤、状态和发布记录，不自动转换为 V3 |
| 新 V3 课件 | 创建时写入 `curriculumId/unitId`、`interactionSchemaVersion=3`、明确环境引用和独立发布快照 |

5→6 不为旧课件猜测课程组织或仿真模板。新旧交互契约按字段显式分流，避免旧课件被新校验误判。

## V6 到 V7 映射

| V6 对象 | V7 行为 |
| --- | --- |
| 新集合 | 增加空 `trainingArchives`，保存P4教员确认后的精确课程版本、任务、尝试、评分、事件和评价引用 |
| 旧任务和尝试 | 保持原交互契约、状态、成绩、事件及确认信息，不转换为V3运行时，不补算归档 |
| 新V3任务 | 分配时冻结发布快照；补训生成独立尝试，旧尝试和已生成归档保持不变 |

6→7 不读取草稿重建历史、不重新计算旧分数，也不把旧确认自动应用到后续补训。

## 兼容行为

- 旧操作/维修 V2 课件机制继续可读、可发布、可分配和运行。P3 新 V3 课件显式绑定 P2 模板并完成制作发布；P4 按交互契约版本将其分流到配置驱动运行时，旧记录不重算。
- 旧 `/operation/topologies/:id` 重定向到 `PROJECT-LEGACY-OPERATION` 的关系页签；该对象只读，复制会新建独立工程、场景和关系数据。
- 旧 URL 自动跳转到规范 URL，并保留对象 ID。
- 显式对象 ID 优先；ID 不存在时显示“当前系统中没有这个课件”，不会回退到最后一条。
- `SUPPORT` 是合法领域，但 P1 后端明确拒绝创建保障教学课件；这不是数据错误，而是阶段边界。

P5 已解除上述阶段门禁：现在 `SUPPORT` 可创建新的保障教学课件。该变化不提高结构版本，也不转换旧记录；新课件才会保存 `supportCaseSnapshot`，新尝试才会生成 `purpose=TRAINING` 的学员副本。P6 复用既有 `issues` 集合并增加类型、状态、核实和来源字段，同样不补写旧问题记录。正式保障任务、预案、演练、执行和归档仍使用原 `purpose=BUSINESS` 对象。

## 上线前备份与验证

1. 停止当前 Java 进程。
2. 完整备份 `backend/.data/` 和上传目录；记录备份时间与文件校验值。
3. 先对备份副本启动新版本，检查工作区列表、旧课件、进行中尝试、报告导出和保障金标摘要。
4. 只有副本验收通过后再安排正式切换；不要将测试内存库复制为业务数据库。
5. 若出现领域缺失或关联错误，停止写入并恢复整个 `.data` 备份，不用当前列表最后一项自动补对象。

## 回滚

- 代码回滚：恢复上一版本 JAR 与前端 `dist`，两者必须来自同一版本。
- 数据回滚：恢复切换前完整 `.data` 备份。不要只替换单个 H2 文件或在进程运行时复制数据库。
- 本轮没有提供自动反向迁移；V3—V7 已增加独立工程、对象能力、调试实例、模板版本、课程组织、V3课件和训练归档，强行降级会丢失新对象，必须通过切换前的完整 `.data` 备份回滚。

- P7 已通过构造的 `schemaVersion=2` 夹具验证连续迁移幂等、旧93分成绩和业务对象不改写，并验证新归档报告及版本来源；真实旧库中的进行中尝试和历史报告仍需在正式切换前用数据库副本逐条对账。
