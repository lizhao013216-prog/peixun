# 三子系统业务流程说明

## 领域边界

| 系统 | 领域值 | 本轮可用主流程 | 不属于本系统的对象 |
| --- | --- | --- | --- |
| 装备使用及作战运用 | `OPERATION` | 操作素材/组网 → 操作课件 → 培训任务 → 训练 → 评价 → 归档 | 维修课件和维修任务；保障正式预案 |
| 装备维修保障 | `MAINTENANCE` | 维修场景 → 维修课件 → 培训任务 → 训练 → 评价 → 归档 | 操作课件和操作任务；保障正式预案 |
| 保障任务筹划及行为演练 | `SUPPORT` | 保障任务 → 预案 → 准备/专项计划 → 演练 → 评估 → 模拟施工 → 对比 → 归档 | 操作/维修训练任务 |

第三系统的教学训练已在 P5 独立开放。它不借用维修任务页，而是使用 `SUPPORT` 课件、任务、尝试、评价和归档；训练案例副本带 `purpose=TRAINING`，不会写入正式保障预案。

## 角色与可见范围

- 制作教员：在当前操作或维修领域创建、编辑、预览和发布课件。
- 审核/培训教员：审核课件、分配当前领域任务、查看当前领域评价并确认证据。
- 学员：只读取本人在当前领域的任务、尝试、课程和反馈；不读取保障正式业务对象。
- 筹划、导调、施工、检查和三级审核角色：继续使用第三系统原业务链，不从训练页面改变正式对象。
- 管理员：用于演示管理和跨系统公共总览。公共总览与域内页面是两个不同范围。

## 关键对象关系

```text
System
  └─ Course(version, domain)
       └─ Assignment(domain, learnerId, courseVersion)
            └─ Attempt(domain, learnerId, events, score)
                 ├─ Feedback(domain)
                 └─ Training record

SUPPORT Task
  └─ Plan(version)
       ├─ Preparation / Subplan
       ├─ Exercise Run / Evaluation
       ├─ Execution / Inspection
       └─ Comparison / Archive
```

共享资源仍可在公共资源中心查看。P1 对旧资源采用显式 `ownerSystem=SHARED`、`visibility=SHARED` 和 `sharedWith` 三领域的兼容映射；资源授权和版本独立化属于 P2。

## 操作与维修培训流程

1. 从对应系统工作台进入课件页，领域由路由确定。
2. 制作教员创建/编辑并预览，独立教员审核，制作教员发布。
3. 教员分配任务时，任务继承课件领域和版本。
4. 学员只在对应系统任务页看到本人任务；开始后形成独立尝试。
5. 操作、帮助、错误、暂停和完成仍使用现有训练运行机制，事件与成绩保存在尝试中。
6. 教员在对应系统评价页查看结果、反馈并确认证据。
7. 对应系统训练归档只显示本领域记录；公共“全部系统记录”才允许跨领域查看。

## 第三系统正式业务流程

1. 建立保障任务并明确对象、期限和目标。
2. 编制预案、资源和准备清单，批准后创建演练。
3. 导调演练并计算评估/敏感性结果。
4. 建立模拟施工，完成签收、报工、检查、整改和复查。
5. 形成对比改进和成果包，经三级审核后发布。

本轮只给第三系统增加独立教学范围入口，没有改变上述算法和状态机。

## 跨系统协作边界

- 允许：公共共享资源；维修培训需求与保障准备状态的既有受控关联；公共记录总览。
- 不允许：用维修菜单承载操作任务；用操作或维修尝试修改正式保障对象；找不到 ID 时自动选择另一系统或最后一条记录。
- 已完成：P2 建立资源授权，P5 建立保障教学副本，P6 建立问题分类、核实和受控转任务；P7 负责最终全量验收。
