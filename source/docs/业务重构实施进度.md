## P0 实际修改

- 根 CI 与 `repository-config/ci.yml` 均以 `source/` 为工作目录，执行前端构建、Maven 验证、两套既有浏览器回归、三领域隔离和运行包冷启动。
- `scripts/sync-release-package.mjs` 从同一次源码构建同步根目录 JAR 和前端 `dist`；使用临时暂存目录，不处理 `backend/.data`。
- `scripts/verify-release-package.mjs` 逐项检查 `index.html` 引用资源，并在 8083 端口用内存库冷启动根目录 JAR。
- 根目录预编译前端与 JAR 已刷新，`start.bat` 的目录关系不变。

## P1 实际修改

- 前端增加 `OPERATION`、`MAINTENANCE`、`SUPPORT` 三领域定义和类型化页面元数据；顶部业务导航改为三个正式系统名称及系统内分组，沿用原布局、色彩、组件和字号体系。
- 新增三套系统工作台；操作、维修各有独立的课件、培训任务、培训评价和训练归档入口。
- 路由中的系统上下文驱动状态查询；课程和训练选择改为按领域保存，显式 ID 找不到时显示错误空状态，不再回退到列表最后一项。
- 旧路径 `/operation/courses/:id`、`/maintenance/courses/:id`、`/maintenance/evaluations`、`/operation/library` 保留重定向。
- 后端增加领域校验、旧快照迁移和按领域/身份的数据投影。任务、尝试、反馈和问题补领域；保障正式业务对象归属 `SUPPORT`；旧资源默认标记为共享。
- 第三系统保留原任务、预案、演练、模拟施工和归档链；教学入口明确说明完整闭环到 P5 才实施。

## P2-A 实际修改

- 三个系统均采用“素材库—场景与设备编排—仿真系统模板库”的同层级入口；公共资源中心改为只读汇总，UI 继续使用原侧栏、面板、色彩和控件体系。
- 新增 `simulationProjects`、`scenes`、`topologies`、`systemTemplates` 四类持久化集合。每个新工程使用独立场景引用，不再读写旧全局 `scene/topology` 单例。
- 工程编辑支持从当前系统可见的已批准素材添加任意数量对象，编辑名称、位置、视图、初始状态和环境，并在保存/刷新后恢复；离开存在未保存内容时提供保存、放弃、取消三种选择。
- 素材默认归属当前系统且为私有；只有显式共享后其他系统才能引用，引用不会改变源素材。后端校验领域、状态、版本和可见范围。
- 工程保存使用 `editRevision` 比较并交换校验；过期窗口返回 `EDIT_CONFLICT`，前端保留本地草稿。
- `schemaVersion=3` 的 2→3 迁移为操作、维修各建立一个确定 ID 的旧配置只读工程；旧设备组网路径进入该兼容工程。复制后才进入新独立草稿。
- 学员后端投影移除制作工程/场景/关系和草稿素材，不能依赖隐藏导航越权读取。

## P2-B 实际修改

- 素材及场景对象声明有限动作、输入/输出端口、数据类型和允许的状态字段；`schemaVersion=4` 的 3→4 迁移补齐这些能力并增加 `simulationPreviews`，不重写旧课件、成绩或保障记录。
- 工程“设备关系与联动”页签可从本工程对象增删同类型输出到输入的连接，编辑动作前置条件和条件命中效果；规则卡用中文说明条件、状态变化和拒绝原因。
- 后端共享规则引擎实际读取保存的连接与规则，校验对象、端口方向、类型、动作、字段、枚举和无环性；明确拒绝循环、脚本和任意表达式，不使用 `eval` 或前端状态补丁。
- 调试开始时冻结工程场景、关系和初始状态，生成独立实例。动作执行记录序号、输入、命中规则、前后状态和拒绝原因；复位只恢复当前实例。
- `NONE` 工程无需创建连接即可执行单对象有限动作；`SIGNAL_GRAPH` 工程通过后端确定性传播处理对象间影响。该规则服务与前端展示分离，可供 P4 直接复用。
- 页面实际演示阀门未就绪拒绝启动、就绪后泵运行、相同输入 `0.5` 在阈值 `0.4`/`0.6` 下产生不同结果，以及两个调试实例互不影响。

## P2-C 实际修改

- 新增统一模板生命周期模块，发布前重新校验工程用途、场景环境、对象编号、素材状态/版本、动作/端口/状态字段、关系规则及跨系统共享依赖闭包。
- 发布在同一事务内创建 `PUBLISHED` 不可变模板版本，冻结场景、对象、环境、关系、规则和素材依赖，并记录来源工程、发布人、时间及前一版本；同一 `commandId` 重放不会重复创建版本。
- 模板库展示用途、所属系统、设备组成、联动模式、主要规则、依赖素材、发布信息、来源工程与版本链；可按发布版本创建独立调试实例，不修改模板。
- “从模板新建工程”生成新的工程/场景/关系 ID；“创建修订”保留模板家族并形成下一版本。修改副本或 V2 不会改变 V1 或其他引用者。
- 跨系统复用同时要求模板授权和全部实时素材依赖可见且版本有效；已发布历史快照在所属系统继续可读。`NONE` 工程可合法发布并明确显示不使用设备联动。
- `schemaVersion=5` 的 4→5 迁移只为旧 `systemTemplates` 补家族、可见范围和使用说明，不转换、删除或覆盖 `templates.type=PLAN` 保障预案。

## P2-D 实际修改

- 操作、维修、保障三个系统分别通过真实上传文件完成“素材导入与审核 → 独立工程 → 场景对象与环境 → 调试动作 → 发布模板 → 从模板创建独立工程”的完整闭环，并在详情页刷新后恢复。
- 新页面仅使用 `simulationProjects`、`scenes`、`topologies`、`systemTemplates` 等项目化集合；旧全局 `scene/topology` 只在明确的只读兼容入口中保留，不作为新建工程的数据源。
- 综合验收同时核对读接口与命令回执的领域范围；同一发布 `commandId` 重放返回同一模板且不增加版本。
- 素材文件直接下载沿用与列表、详情相同的可见范围：所属系统可下载，未共享的跨系统请求返回 404，显式共享后目标系统可下载。
- 增加真实 `schemaVersion=2` 夹具；P3 后续扩展后连续迁移至 V6 两次，新工程/场景/关系/模板/课程组织数量稳定，旧课程、任务、成绩、保障任务、预案及原模板对象完全不变。
- P2-D 未新建重复业务模块，只补足 P2-A/P2-B/P2-C 的三系统端到端证据、迁移夹具和访问边界验收；UI 继续沿用原有组件和视觉体系。

## P3 实际修改

- 新增 `curricula` 课程组织集合，保存课程目标、受众和课时；原 `courses` 继续作为课件版本集合。V3 课件记录 `curriculumId/unitId`，旧 V2 课件不改写。
- 交互契约 V3 课件必须显式选择一个可见的已发布仿真模板版本，服务端解析并锁定模板、场景、关系和素材依赖引用；普通保存只接受教学字段，不读取旧全局 `scene/topology`。
- 新课件默认提供 5 个稳定编号的空白步骤，支持新增、复制、删除、上移/下移和拖动排序；目标对象、有限动作、参数和状态字段均来自绑定模板，不固定四设备或 8/10 步。
- 每步支持类型化动作参数、可选前置状态条件、完成判断、结果说明、分值和引导/自由/演示模式；草稿允许半成品保存，预览、提交和发布使用严格校验。
- 换绑模板会列出已经失效的目标对象或动作并阻止提交，不自动把原步骤替换成其他对象。只修改说明或评分时环境引用保持完全不变。
- 制作预览调用 P2 的 `SimulationRuleEngine` 执行真实有限动作和联动规则，不创建培训任务、尝试或成绩。
- 提交审核时冻结审核快照；制作者不能审核自己制作的课件。发布快照冻结环境、设备能力、步骤和评分；V2 修订不改变 V1。
- 新 V3 课件由 P4 运行时按 `interactionSchemaVersion=3` 显式分流，不会落入旧运行器；新建弹窗保留显式 V2 兼容选项，原操作/维修训练金标继续可复现。
- `schemaVersion=6` 的 5→6 迁移只增加空 `curricula` 集合，不改写旧课程、任务和历史训练记录。

## P4 实际修改

- 分配 V3 课件时冻结已发布快照及精确课程版本；训练开始时从任务快照创建独立仿真运行实例，不读取制作草稿、全局 `scene/topology` 或课件当前版本。
- 学员页面按快照动态显示对象、有限动作、类型化参数、前置条件、当前对象状态和预期结果；旧四对象场景及 V2 步骤继续走兼容显示。
- 正确动作复用 P2 `SimulationRuleEngine`，记录完整命令、步骤、操作者、对象、动作、参数、前后状态、结果、原因、分数变化、序号和时间；错误对象、动作、参数或前置条件不推进步骤。
- 动作通过后进入“等待学员继续”状态，只有显式继续才前进或完成；重复动作、重复继续不会重复计分或推进。暂停、刷新和恢复直接读取持久化尝试状态。
- 新课件按步骤分值累计，并扣除发布快照中的错误/帮助分；分数限定在0到总分。正确率只按已通过步骤和业务错误计算，帮助及技术故障不进入分母，无业务操作时显示暂无结果；演示模式不计分。
- 平台失败记录为技术故障且不扣分；现有命令回执幂等保护避免相同命令重复执行，平台重复/乱序模拟不会额外推进步骤。
- V3首版明确支持个人训练和不计分演示，不保留仅靠 `scope=TEAM` 的伪团队能力；旧V2团队演示兼容不变。
- 台位采用带领域和明确映射的独立记录，信号必须指定活动 `attemptId` 和映射点；断连、未映射、跨领域、非本人或已完成实例均明确拒绝，不再修改全局拓扑。
- 完成时生成评价摘要；教员确认精确尝试后创建包含课程版本、任务、尝试、评分规则、事件和评价的 `trainingArchives` 归档。补训创建新尝试并清除任务上的旧确认，不改写旧尝试或旧归档。
- `schemaVersion=7` 的 6→7 迁移只增加空 `trainingArchives` 集合，不重算旧成绩或转换旧训练尝试。

## P5 实际修改

- 保障系统开放与操作、维修一致的课程、课件、培训任务、培训评价和训练归档入口；原任务、预案、演练、模拟施工和三级归档链保持不变。
- 保障课件创建时冻结教学案例、资源和工序副本。开始训练后再生成带 `purpose=TRAINING`、`attemptId` 和 `ownerLearnerId` 的学员独立副本，不调用正式预案保存或执行命令。
- 学员按“理解任务10分—配置资源20分—编制方案20分—计算验证20分—事件处置20分—提交复盘10分”完成六阶段训练。
- 初始计算、到货延迟和加急处置均由后端 `ScheduleEngine` 计算；验收样例分别得到 240、300、255 分钟，前后方案均保留事件证据。
- 训练结果将方案工期/费用与学习成绩分列。教员确认后沿用 P4 归档，课程版本、任务、尝试、教学事件和评价均可追溯。
- 两名学员从同一发布课件启动后拥有独立资源、工序、事件和成绩；学员无权调用正式 `plan.*` / `run.*` 命令，训练过程不增加或修改正式预案。

## P6 实际修改

- 训练问题为可选后置流程；没有问题仍可完成、评价、确认和归档。
- 问题分为 `CONTENT`、`LEARNING`、`PLATFORM`、`EQUIPMENT_SUPPORT`，统一经历待分流、处理中、已解决、已关闭状态并保留处理历史。
- 内容问题创建关联问题号的课件修订草稿；学习问题创建补训任务且不覆盖原成绩；平台问题创建技术处理单且不扣学习分。
- 疑似装备保障问题必须由保障筹划人员填写核实意见；只有来源训练已完成、问题已核实且确认表完整时才创建正式保障任务。
- 正式任务保存 `sourceIssueId`、`sourceAttemptId` 和精确课程引用，形成“任务→问题→训练→课程”来源链；即使使用不同命令号重复提交也只创建一个任务。
- 学员只能登记本人训练问题；教员负责教学/平台分流，保障筹划人员负责核实和转任务，角色边界由后端校验。

## P7 实际修改

- 新增 `verify-p7-three-routes.mjs`：在一个新建测试工作区中依次完成操作系统“联动工程→调试→模板→5步课件→训练→评价归档”、维修系统“无联动工程→6步课件→训练归档→补训”，以及保障系统“教学课件→240/300/255方案处置→100分评价→归档报告”。
- 综合浏览器回归扩展到 1440px、1366×768 和 390px；1366×768 页面实际显示维修旧金标 88 分、2次错误、1次帮助和83.33%正确率，关键按钮无横向遮挡。
- 原 100分操作、88/93分维修、保障 240/300/255/250/270 工期费用、三级归档顺序、领域/学员隔离、深链接和 V2 兼容由 48 项后端测试及阶段专项共同回归。
- 新增 `verify-p7-delivery.mjs`，逐文件比较源码构建与根目录发布包，核对 Maven 报告、视觉证据、CI覆盖和 `start.bat` 指向。
- 根 CI 与 `repository-config/ci.yml` 增加 P5/P6、P7 三路线和最终交付一致性校验；P2—P7 浏览器专项均进入持续集成。
- 所有自动化继续使用独立 H2 内存库；根目录用户数据库不作为测试库、不被同步脚本覆盖。

## 已知边界和风险

- P0—P7 代码与自动化验收已完成，但没有对用户真实旧数据库副本执行迁移演练；当前结论来自 `schemaVersion=2` 夹具、独立内存库和历史对象不变断言。
- Chromium 已覆盖 1440px、1366×768 和390px；未在 Firefox、WebKit 或真实头显/外设上验证，真实VR也不属于本指南范围。
- 当前数据为演示/合成数据，方案结果用于验证系统计算与来源链，不等同于真实装备工程结论。
