# 实现范围与验证记录

验证日期：2026-09-21。版本：Demo 1.2。

## 1. 本次交付范围

实现三系统从输入、编制、运行到评价、改进的业务主线，提供34个页面入口。不是根目录需求方案全部细项的最终验收结论；建设方案仍保留作为正式系统深化基线。

| 业务域 | 当前实现 | 边界 |
| --- | --- | --- |
| 公共工作台 | 实时业务计数、流程进度、跨系统入口、搜索与角色/工作区切换 | 合成数据共享工作区，非正式多租户 |
| 资源中心 | 文件上传下载、分类搜索、派生版本、处理任务、审核 | 几何转换和轻量化为平台模拟；媒体不进行转码 |
| 场景编辑 | 对象选择、取景、阀门关键帧预览、行为节点文字、环境/材料/LOD/刚体约束参数、模板保存 | SVG交互示意；没有通用三维编辑器、任意节点图解释器或物理求解 |
| 操作组网 | 四设备启动就绪条件、阈值告警、停止复位、台位连接与模拟信号 | 四设备固定规则；外设协议和点位转换未接真实设备 |
| 课程发布 | 两类课程、步骤编辑、独立审核、模拟构建、失败重试、修订版本 | 浏览器运行可用；独立EXE/APK等原生包不生成 |
| 训练运行 | 8/10步骤、顺序与对象检查、错误/帮助计分、暂停、协同控制权、问卷、证据确认 | 示意交互；演示模式需逐步操作；没有语音讲解、XR输入和视频录像 |
| 任务与资料 | 任务/WBS、示例履历去重校验、资料记录、人工结构化分析 | 历史来源为合成PLSE数据；分析不是自动故障诊断 |
| 资源和筹划 | 人员、器材、物料、设施元数据、维修周期窗口、预案模板硬条件过滤、排程与费用 | 多任务排序页面不等于跨项目联合最优调度；资源按单个占用单元处理 |
| 六类准备 | 培训需求回流、采购/调拨单据状态、五类专项计划提交审核 | 准备单据是独立流程演示，不扣减全局实库；演练使用自己的库存账本 |
| 专业计划 | 修复/更换成本比较、路径候选评估和采纳 | 路径几何可行性由固定平台模拟结果提供 |
| 保障演练 | 离散事件推进、延迟注入、加急分支、资源快照、独立发运/收货/领用账本、只读复盘 | 主案例为固定2件备件调拨；不是通用物流运输网络求解 |
| 评价与敏感性 | AHP一致性、模糊综合评价、DEA、五个固定到货样本及完整记录 | DEA限单投入单产出；未实现多投入多产出、随机蒙特卡洛和人员离岗敏感性专用界面 |
| 模拟施工 | P1签收准备、首批固定样例报工、四项检查、整改、复查、交接 | 实绩来自示例操作，不接真实现场；批量报工样例要求到货135分钟 |
| 对比和归档 | 预计/实绩差异、P2版本、三级审核、退回补充、发布复用 | 报告以MD记录导出；没有电子签章和法定档案接口 |
| 可靠性 | 服务端角色约束、修订冲突、命令幂等、轮次隔离、审计、回调去重防回退 | 演示身份可切换；未提供生产SSO、组织行级读取权限或高并发容量保证 |

## 3. 自动化检查

后端`mvn verify`包含13项JUnit测试方法，其中业务链测试连续覆盖多个状态转换和结果断言：

| 测试文件 | 方法数 | 内容 |
| --- | ---: | --- |
| `ScheduleEngineTest` | 6 | 三情景/P2、资源不可用、循环依赖、资源冲突、三评价算法、非法矩阵、生命周期 |
| `BusinessFlowTest` | 7 | 完整维修培训→筹划→施工→归档链；幂等/权限/版本/轮次；技术失败和团队证据；重复/迟到回调；步骤对象/动作和结果；重复训练保护；步骤完整性及旧课兼容 |

这些方法不是对根目录56条验收用例的逐项覆盖，不能将“13项测试通过”解读为“全部原始验收项通过”。

前端通过TypeScript校验和Vite生产构建。浏览器使用Chromium，测试脚本自动建立完整HTTP业务案例；检查34个路由、1440px桌面布局、390px工作台和折叠菜单、演练复盘账本、组网按钮、课程表单及刷新后的记录保存，以及未处理页面异常。截图同时检查工作台、场景编辑、训练、演练、施工、组网和归档。

测试运行环境使用内存数据库，业务数据由命令产生；本地正常启动使用H2文件持久化。Docker配置与CI工作流已编写，本次没有实际运行Docker构建，也没有把未执行的远端CI记为通过。

## 4. 后续验收顺序

先以本Demo确认客户对三系统边界、角色分工、状态和数据口径的理解。再按原功能列表逐项补充参数、异常场景和正式接口，特别关注多装备配置、联合资源约束、真实VR平台能力和生产身份数据权限。

新增功能要保持三个不变量：历史版本不被新编辑覆盖；演练与施工实绩不混写；技术故障不作为业务错误扣分。发布前继续运行现有金标和浏览器脚本。
