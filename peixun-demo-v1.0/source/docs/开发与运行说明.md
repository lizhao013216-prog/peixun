# Demo开发与运行说明

## 1. 技术选择与项目边界

前端使用Vue 3单页应用，TypeScript负责开发期校验，Vue Router提供33个页面入口，Vite负责构建。后端使用Java 17、Spring Boot 3.5和JDBC事务。H2数据库以文件方式保存工作区、命令回执和审计记录。

选择单体服务是为了简化Demo启动和调试。正式系统拆分时，可沿训练、筹划、演练、施工、归档边界提取服务。本次不引入需要额外部署的消息队列、对象存储、身份中心或真实虚拟现实引擎。

后端模块分工：

| 类 | 职责 |
| --- | --- |
| `DemoController` | HTTP入口、演示会话、上传和下载 |
| `DemoService` | 事务、角色授权、工作区、版本校验、幂等与审计 |
| `TrainingModule` | 资产、场景、组网、课件、发布、训练与证据 |
| `PlanningModule` | 任务、履历、资源、预案、单据、演练和评估 |
| `ExecutionModule` | 签收、报工、检查、整改、对比和成果归档 |
| `ScheduleEngine` | 工序依赖与资源日历排程、费用、敏感性、评价 |
| `VirtualPlatformPort` | 平台任务结果和交互能力的统一接口 |
| `MockVirtualPlatformAdapter` | 成功、失败、超时、重复和乱序回调模拟 |
| `Seed` | 合成数据、基础资源、标准工序与角色 |

场景使用可交互SVG示意图。它能选择设备、显示状态、切换取景、预览阀门关键帧，但不承担三维几何和物理计算。后续接入厂商平台时，应扩展适配接口和前端场景宿主，保留业务命令及记录逻辑。

## 2. 本地运行

推荐Node.js 24、JDK 17、Maven 3.9。依赖版本由`frontend/package-lock.json`和`backend/pom.xml`约束。

开发模式分别在`frontend`运行`npm ci`、`npm run dev`，在`backend`运行`mvn spring-boot:run`。前端5173端口将`/api`代理到后端8080端口。

生产构建模式在根目录运行：

```bash
npm --prefix frontend ci
npm --prefix frontend run build
mvn -f backend/pom.xml package
cd backend
java -jar target/peixun-demo-1.0.0.jar
```

页面和接口均由8080提供；不需要另起Vite。直接刷新深层页面由`SpaController`回退到首页，再交给Vue Router解析。

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PORT` | `8080` | 后端监听端口 |
| `BIND_ADDRESS` | `127.0.0.1` | 本地演示监听地址 |
| `DB_URL` | `jdbc:h2:file:./.data/peixun;DB_CLOSE_ON_EXIT=FALSE` | 数据库位置；相对后端工作目录 |
| `DB_PASSWORD` | 空 | H2密码 |
| `CHROMIUM_EXECUTABLE` | Playwright安装目录 | 浏览器验收时可指定Chrome可执行文件 |

Windows PowerShell可逐行执行相同命令。若Java或Maven无法识别，请先确认`java -version`、`mvn -version`，以及`JAVA_HOME`和`PATH`。端口冲突时修改相应环境变量；开发模式后端改端口还需调整`frontend/vite.config.ts`的代理目标。

## 3. 数据和案例

默认数据库位于`backend/.data/peixun.mv.db`，上传文件位于`backend/.data/uploads/`。这些文件不提交Git。停止服务后整体备份`.data`目录；恢复时同样停止服务后替换目录。

工作区保存完整业务快照，ID在工作区内解析。克隆工作区复制业务对象，后续操作独立。重置仅对当前工作区生效，运行轮次`epoch`递增；旧轮次请求被拒绝。SQL审计表保留历史轮次，前端展示的是当前轮次业务事件。

运行`node scripts/load-demo.mjs`可新建完整案例。可自定义后端地址和名称：

```bash
node scripts/load-demo.mjs http://127.0.0.1:8080 客户汇报案例
```

该脚本使用正常HTTP命令逐项生成业务记录，包含审批、异步发布等待、训练计分、演练和归档；没有直接写入终态得分或工期。重复运行会新建工作区。选择工作区后可复盘，也可克隆后继续改参数。

## 4. 当前Demo接口契约

根目录`Demo数据与接口契约.md`是完整目标设计。本实现为单体Demo采用**命令接口**，尚未逐项落地该文档中的资源化REST路径；调用方应以本节和代码为准。

| 方法与路径 | 内容 |
| --- | --- |
| `GET /api/demo/health` | 服务状态 |
| `GET /api/demo/bootstrap` | 演示身份与工作区目录 |
| `POST /api/demo/session` | `{actorId}`换取演示Bearer令牌 |
| `GET /api/demo/state?workspace=ID` | 获取业务快照、结算到期模拟任务 |
| `POST /api/demo/commands?workspace=ID` | 执行业务命令，返回结果和最新快照 |
| `POST /api/demo/workspaces` | 管理员新建或克隆工作区 |
| `POST /api/demo/uploads?workspace=ID` | multipart源文件上传，单文件最多20MB |
| `GET /api/demo/assets/ID/file?workspace=ID` | 下载已上传源文件 |
| `GET /api/demo/reports/集合/ID.md?workspace=ID` | 导出Markdown记录 |

会话之外的业务接口要求`Authorization: Bearer TOKEN`。命令请求示例：

```json
{
  "action": "task.create",
  "payload": {"name": "泵组维修保障", "deadline": 270},
  "commandId": "客户端生成的唯一UUID",
  "runEpoch": 1,
  "expectedRevision": 0
}
```

处理顺序为工作区锁定、轮次检查、角色授权、幂等查询、修订检查、业务转换、持久化和审计。同一轮次、同一身份和相同内容的重复命令返回原回执；命令ID复用但内容变化返回409。快照已更新返回`REVISION_CONFLICT`；前端刷新后自动重试一次。工作区已重置返回`STALE_EPOCH`，前端刷新，不自动重放旧操作。

核心命令前缀包括`asset`、`scene`、`topology`、`course`、`training`、`task`、`plan`、`run`、`execution`、`inspection`、`rectification`、`comparison`、`archive`。命令实际字段可查相应模块中的`apply`方法；完整调用样例见`load-demo.mjs`。

## 5. 计算和状态约束

- 审批后的课程和预案通过新版本修订；原业务记录继续引用原版本。
- 单个资源在当前排程中按一个可占用单元处理，排程检查前置、人员可用性和时间窗口；不实现通用多容量混合整数优化。
- 预案、演练、施工分别保存计划、推演、实绩数据。每次演练有独立资源快照和调拨账本。
- 实绩样例固定使用P1的135分钟到货条件，报工、检查、整改和交接逐步推进。费用按预案冻结的人员费率计算。
- 本次培训证据由教员确认个人训练后产生。团队训练和虚拟参与者不生成个人培训通过证据。
- 一级、二级、三级审核逐级进行；退回保留旧意见，补充说明后提交新轮次。
- 发布任务用到期时间和回调序号模拟，前端轮询触发结果结算；此处没有独立消息中间件或真实异步转换服务。

## 6. 继续开发建议

先以当前金标测试锁定业务口径，再扩展功能。新命令应同时明确角色、对象状态、版本边界与失败后的处理方式。

正式系统深化优先处理以下事项：真实身份认证和组织级数据权限；分表建模与迁移；对象存储和扫描；持久化任务队列与回调签名；厂商SDK适配；多设备和多项目资源约束；正式报表模板与审计归档策略。当前演示身份可直接切换，工作区是合成数据共享空间，不应作为生产认证方案沿用。

新增界面沿用共享组件和`style.css`变量；避免在页面自行堆叠不同色彩、按钮和状态规则。字段变化应同步更新金标案例、界面说明和本文件。
