# Demo演示操作手册

## 1. 准备方式

初次启动后可以从空业务工作区完整操作，也可以执行根目录的`node scripts/load-demo.mjs`建立完整案例，刷新页面后切换工作区。后者适合客户汇报和结果复盘；需要演示新建操作时，在“演示管理”中新建或克隆一个工作区。

右上角“演示指引”提供六个关键入口。全局搜索支持按页面名称查找功能。导航按公共服务、操作训练、维修培训、筹划、演练、执行归档分组。

本Demo采用合成的“演示船A—通用泵组”，所有参数均为业务演示口径。

## 2. 角色切换

| 演示身份 | 主要操作 |
| --- | --- |
| 制作员 AUTHOR | 资产处理、场景、组网、课程编排、提交与发布 |
| 教员 INSTRUCTOR | 资产与课程审核、分配训练、确认证据 |
| 学员A/B | 训练、协同、问卷 |
| 筹划员 PLANNER | 任务、预案、准备、对比、归档提交和发布 |
| 一级审核员 REVIEWER_L1 | 预案与专项计划审批、一级归档审核 |
| 导调员 DIRECTOR | 演练、导调注入、优化分支 |
| 施工员 WORKER | 签收、开工准备、报工、整改、交接 |
| 验收员 INSPECTOR | 首次检查和复查 |
| 二/三级审核员 | 对应级别的归档审核 |
| 演示管理员 ADMIN | 管理工作区、切换模拟配置和重置，可协助大部分业务操作 |

课程和预案不能由创建者审核自己的内容；成果包三级审核必须使用对应审核身份，管理员也不能跳级。

## 3. 操作训练系统

1. **资源中心**：查看预置资源，或上传源文件/创建模拟资源。点击“派生处理”后在发布中心查看任务结果，切换教员批准派生资源。源版本保留。
2. **素材工程/场景编辑器**：选择泵组、阀门、控制器和传感器。调整材料、环境、取景、刚体、约束轴、UI模板、关键帧和行为节点，保存场景。时间轴拖动预览阀门角度，预览不会产生训练成绩。
3. **设备组网**：阀门未就绪时尝试启动，应出现条件未满足提示。置为就绪后启动；降低传感器数值到阈值以下，泵组进入异常状态。停止后可复位。修改阈值后保存。
4. **系统模板**：保存当前场景与组网配置；应用模板后可创建另一门课程。模板记录配置快照。
5. **台位与外设**：建立`mock://`台位，选择协议与点位说明。连接后发送`button.start`模拟信号；断开后发送被拒绝。此处不会连接真实设备。
6. **操作课程**：制作员创建课程、编辑8步说明、提交审核；教员在发布中心审核；制作员发布，等待模拟构建完成。课程进入已发布状态后，教员分配给学员A。
7. **训练运行**：以学员A进入提示、自由或演示模式，逐步操作。选择错误对象会记错误，帮助单独扣分；暂停时不能提交操作。完成后查看操作记录及MD报告。
8. **训练资源归档**：从已完成记录创建问题单，由筹划员人工确认生成保障任务，保留训练来源。

可用两个浏览器窗口分别切换学员A/B，加入同一团队会话。申请对象控制权后操作；30秒租约内另一成员不能抢占。主持人可切换交互/评审模式。团队记录不充当个人培训证据。

## 4. 筹划与维修培训联动

1. **任务建模**：筹划员创建“泵组维修保障”任务，截止时间270分钟。查看维修范围和WBS。
2. **装备履历**：导入示例履历，首次应显示8条有效、1条重复、1条缺主键。修复后再导入，只新增修复记录。可补充技术资料和结构化分析结论。
3. **资源建模**：查看6名人员、工具/检测工位、远端与本地物料、9类设施元数据。演示远端4件、本地0件、需求2件。预案建立后使用冻结资源快照，修改资源后需在草稿重新绑定才进入新计算。
4. **全寿命筹划**：周期6个月，24个月内4次维修、每次2天，停机8天、可用712天。改为8个月周期，可用714天；增加第5个月高强度维修后新增窗口。
5. **预案库/预案编制**：选择匹配的泵组维修模板，形成P0。确认八工序、到货90分钟、运输费用60；计算得到工期240分钟、总费用965。提交后切换一级审核员批准。
6. **六类准备**：查看人员、物料、工具、资料等准备项目。发送培训需求；建立调拨单并推进审批、发运、收货、关闭。此处单据与推演账本独立，避免准备演示改变演练起始库存。
7. **维修课件**：制作员新建课程时关联培训需求。编排10步并提交、审核、发布；教员分配学员A。
8. **维修训练**：学员A在个人提示模式下，先选择错误对象执行2次，再请求帮助1次；选择泵组完成10步。应得88分，正确率83.33%，错误率16.67%。
9. **培训评估**：提交问卷；教员查看成绩并确认本次培训证据。回到筹划准备页，关联培训需求应已完成。此证据只服务当前业务，不修改正式资质。

## 5. 保障演练与优化

### 5.1 三种情景

导调员新建演练时，选择已批准P0。

| 情景 | 操作 | 期望工期 | 等待 | 总费用 |
| --- | --- | ---: | ---: | ---: |
| 正常 | 到货90，运输60，运行至结束 | 240 | 0 | 965 |
| 延迟 | 创建延迟情景，T+60自动改到货为180 | 300 | 60 | 965 |
| 加急 | 在延迟演练到达T+60后建立独立分支，到货135、运输100 | 255 | 15 | 1005 |

支持下一事件、自动推演、暂停和运行至结束。导调只能调整尚未到货的备件时间。事件、甘特图、仿真时钟与当前账本同步。

完成后进入“过程复盘”，拖动时间轴：T+30时远端2、在途2、本地0、累计领用0；最终远端2、在途0、本地0、累计领用2。复盘只读，不会再次发运或领用。三次演练账本互不污染。

### 5.2 指标与敏感性

| 功能 | 输入 | 结果 |
| --- | --- | --- |
| AHP | 默认互反矩阵、指标80/90/100 | 权重0.5/0.3/0.2，CR约0，得分87 |
| 模糊评价 | 默认三项权重和隶属矩阵 | 综合隶属度0.49/0.38/0.13，87.2分 |
| DEA | 默认A/B/C三个单投入单产出样本 | 效率0.8/1/0.64 |
| 到货敏感性 | P0工序，90/120/135/150/180分钟到货 | 工期240/240/255/270/300，均值261，准时率80% |

每个敏感性样本保存独立演练记录。评价输入与结果也保存，可导出。AHP非互反或一致性不通过时应拒绝计算。

## 6. P1施工与P2归档

1. 回到批准的P0，创建P1新版本。到货改为135分钟、运输100，预期工期255、费用1005。提交并批准。若P0培训尚未确认，请先完成维修培训证据确认再复制P1。
2. 下发P1模拟施工。施工员签收、确认开工准备。缺少培训证据或维修人员不可用时，准备不能通过。
3. 提交首批模拟实绩，记录到首次检查结束T+240。验收员逐项提交四项检查，第3项不通过，其余通过。
4. 施工员提交整改说明，追加10分钟双人整改；验收员对第3项复查通过，追加5分钟检测；施工员完成15分钟交接。
5. 结果应为：工期270、人工770、物料200、运输100、总费用1070、人工480人分钟。首次合格率75%、最终合格率100%，四个检查项保留五条检查/复查记录。
6. 对比P1与实绩：工期偏差+15分钟/+5.88%；费用+65/+6.47%。填写原因，保存对比记录。
7. 创建P2改进草稿，新增10分钟装配前检查，到货提前至120。批准并再次演练：工期250、人工725、总费用1025。质量改进仍是待实际验证的建议。
8. 为P2建立成果包，检查本版完成演练、P1验收施工、对比报告的关联。提交三级审核。
9. 一级通过、二级退回。筹划员补充改进依据，重新提交；一级、二级、三级依次通过。历史两轮共5条审核意见保留。
10. 筹划员发布成果，预案库出现可复用模板。新任务使用该模板时带入P2九工序及到货、费用参数，再绑定当前资源形成新草稿。

## 7. 异常演示和常见问题

在“演示管理”设置平台下一次失败或超时，再发布课程或执行训练动作。课程进入构建失败后可重试；技术失败不会计为学员错误。重复/乱序模拟针对发布或资产处理任务回调，历史回调及忽略数量保存在任务记录中。

| 现象 | 处理 |
| --- | --- |
| 提示无权限 | 在右上角切换对应演示身份 |
| 自己不能审核 | 制作员提交，教员审核；筹划员提交，一级审核员批准 |
| 施工不能准备 | 检查P1继承的培训证据，以及M1/M2是否可用 |
| 提示实绩样例需要135分钟 | 选择P1金标预案，当前批量实绩样例固定使用这一条件 |
| 归档缺本版演练 | 对正在归档的P2运行一次完整演练，再建立成果包 |
| 资源日历不足 | 检查人员/工具可用区间和工序配置，草稿重新绑定资源 |
| 其他窗口数据已更新 | 前端刷新快照并重试一次；再次冲突时重新操作 |
| 改资源后旧结果未变化 | 原版本使用冻结快照，建立草稿或新版本后重新计算 |

建议汇报顺序：工作台业务总览 → 操作组网和课程 → 维修培训88分 → 三情景演练 → P1返工验收 → P2归档复用。完整手动操作可分段进行；完整案例可在15～20分钟内集中展示关键过程。
